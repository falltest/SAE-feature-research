# Бимодальность активаций SAE-фич как маркер feature splitting

Изучал, есть ли в Gemma Scope фичи, у которых сила активации распределена
бимодально. Исходная идея была такая:
одно направление активируется то слабо, то сильно в зависимости от
контекста, и это как-то влияет на генерацию.

Не подтвердилось. Бимодальные фичи оказались просто недоразделёнными: каждая
такая фича склеивает два разных лексических триггера в одном направлении.
В словаре пошире они расщепляются на отдельные специализированные фичи.

## Что получилось

Взял пять бимодальных фич из 16k-словаря, посмотрел, на каких токенах каждый
пик срабатывает.

| фича 16k | слабый пик | сильный пик |
|---|---|---|
| 10301 | преамбула LaTeX, 298 токенов | `usepackage` — 99% |
| 2241 | `{` внутри формул | `{` в `\end{...}` — 100% контекстов |
| 11343 | `Fig`, `fig`, `Phys`, 349 токенов | `www` — 92% |
| 12428 | обломки URL, 527 токенов | `://` — 98% |
| 1673 | `Moreover`, `example`, 357 токенов | `However` — 55% |

Паттерн одинаковый везде: сильный пик — это один конкретный токен, слабый —
всё вокруг него.

Проверил это количественно: из 155 частых токенов по всем пяти фичам **153
ведут себя бинарно** — либо всегда в слабый пик, либо всегда в сильный. Например,
`' Moreover'` не попадает в сильный режим ни разу из 519 срабатываний — просто
ноль.

### Далее в латенте 65k

Нашёл ближайшие по косинусному сходству фичи в 65k-словаре и прогнал корпус,
чтобы посмотреть, на чём они реально стреляют.

| 16k | 65k | доля триггера | уникальных токенов |
|---|---|---|---|
| 10301 | 16822 | 9.9% → 97.0% | 299 → 5 |
| 2241 | 46324 | 39.4% → 99.9% | 275 → 4 |
| 11343 | 45031 | 32.8% → 94.6% | 353 → 19 |
| 12428 | 62900 | 49.1% → 96.7% | 532 → 23 |
| 1673 | 13257 | 16.0% → 71.6% | 361 → 27 |

4 из 5 явно расщепились. Пятая (1673) формально не дотягивает до порога 80%,
но там расщепление самое интересное: одна фича «дискурсивные коннекторы»
разложилась как минимум на шесть по типу связи — `However` (13257),
`Moreover`/`Furthermore` (41813), `therefore` (62410), `Nevertheless` (34913),
`but` (56876), `yet` (33430). Просто `However`, `however` и ` However` — это
три разных токена одного слова, поэтому метрика занижена.

### Побочное наблюдение про косинусное сходство

В двух случаях ближайший по косинусу сосед в 65k — это не та фича, которая
специализируется на нужном триггере:

- 11343: нужная фича на косинусе 0.428, топ-1 по косинусу (0.942) — менее чистая (85% vs 94.6%)
- 1673: нужная на 0.453, топ-1 (0.887) — 39.3% vs 71.6%

Геометрически ближайший сосед оказался смешанной остаточной фичой. Это значит,
что косинус decoder-векторов можно использовать только как первичный фильтр,
а смотреть надо на реальное поведение.

## Полная схема всего алгоритма

Три прогона корпуса. Всё сразу хранить нельзя: 16k фич × 30M токенов × L0 ≈ 90
= сотни гигабайт.

**Пасс 1** (30M токенов) — прогон через модель + SAE, копим только гистограммы
активаций по всем фичам. Обе ширины словаря в один проход. Выход = несколько
мегабайт.

**Скрининг** (локально, по гистограммам) — восстанавливаем псевдо-сэмпл из бинов
с джиттером в log10-шкале. Критерий бимодальности: dip-тест Хартигана (p < 0.05),
расстояние между пиками ≥ 2σ, вес меньшего пика ≥ 5%.

BIC из критерия убран намеренно. На синтетике экспонента даёт `dip_p = 0.99`
и одновременно `bic_gain = +670` — BIC ловит скошенность, а не два режима.
Проверено на 500 синтетических унимодальных фичах в той же сетке бинов: ноль
ложных срабатываний.

**Пасс 2** (10M токенов) — прогон только по 10 отобранным фичам:
значение, токен, окно контекста. Порог между пиками ищем по провалу в гистограмме
сырых данных.

**Пасс 3** (10M токенов) — косинусная близость decoder-векторов 16k vs 65k,
топ-8 кандидатов на каждую фичу, прогон корпуса по кандидатам.

### Проверки

- **Негативный контроль** — пять унимодальных фич с похожей density. При
  искусственном разрезе по медиане их верхняя половина содержит 146–1974
  уникальных токена (топовый — 3–19%). У бимодальных: 2–9 токенов, топовый
  55–100%. Разница на два порядка — эффект не наводится методом.
- **Устойчивость к порогу** — сдвиг границы между пиками ±30% не меняет вывод:
  сильный пик остаётся одним токеном в 79–100% случаев.
- **Сверка проходов** — форма распределений в сырых данных пасса 2 совпадает
  с гистограммами пасса 1, корреляция 0.99–1.00.

## Запуск

Использовал Kaggle с GPU + принятая лицензия Gemma 2 на HuggingFace, токен в Secrets.
`corpus_loader.py` подключается как Kaggle Dataset или копируется в ячейку.

```
notebooks/pass1_gemma_screening.ipynb   гистограммы по всему словарю
src/bimodality_screen.py                скрининг (локально)
notebooks/pass2_contexts.ipynb          контексты для отобранных фич
notebooks/pass3_splitting.ipynb         проверка расщепления в 65k
```

```bash
python src/bimodality_screen.py pass1_gemma_checkpoint.npz --width 16k --out metrics_16k.csv
```

Пасс 1 — несколько часов, пассы 2–3 примерно в три раза быстрее. Ноутбуки
чекпоинтятся и переживают обрыв сессии. Для длинных прогонов — Save & Run All,
не интерактив.

## Ограничения

- **Корпус.** Gemma Scope обучалась на закрытых данных Google, The Pile — прокси(похожий датасет).
  Density и форма распределений могут отличаться.
- **fp16.** T4 не умеет bf16 на tensor cores, Gemma 2 штатно в bf16. Влияние
  на точность активаций не измерялось.
- **Один слой.** Всё на слое 12, остальные не проверялись.
- **Выборка маленькая.** Разобрано 5 фич из 2207 бимодальных. Чтобы утверждать
  про все бимодальные фичи — нужна проверка на сотнях.
- **Разрешение гистограммы.** `BIN_MIN = 1e-3` выбран до того, как стал известен
  реальный диапазон JumpReLU (2.4–100). Из 64 бинов занят 21. На выводы не
  влияет, но при повторе стоит сузить.
- **Расщепление в 65k неполное.** 65k#56570 по-прежнему смешивает оба триггера
  (46.7% сильных токенов и 16.3% слабых).
- **Порог 80% произволен** и не учитывает морфологию — `However`, `however`
  и ` However` считаются разными токенами.
